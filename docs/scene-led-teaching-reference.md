# 场景驱动的讲解与动效参考

本文件记录用户提供的《鸡兔同笼》讲解视频中可复用的教学编排与视觉推进规律，用于指导 Math Motion Lab 后续新建或视觉重做的课程。

参考视频是一段约 2 分 47 秒、`1280×720` 的线性讲解动画。只借用其可控的教学方法、场景连续性和动效语义，不复制水印、角色造型、手写字体、纸张纹理、品牌元素或精确构图。

## 1. 核心判断

视频有效的原因不是“手绘风”，而是它把讲师的话转成了同一数学场景中的连续变化：

- 已知条件先进入画面，成为后续步骤的固定锚点。
- 同一排头和腿贯穿推理，不因讲到新概念就换成另一套图表或卡片。
- 讲师每引入一个概念，画面只增加或改变与该概念对应的对象。
- 先让学生看见变化，再在变化旁边出现算式和术语。
- 算式不是独立答案板，而是对刚刚发生的视觉动作进行命名。
- 小数量例子负责建立直觉，大数量原题负责迁移，最后用新对象检验方法是否真正通用。

后续课程的目标不是制作“会翻页的网页”，而是制作“可由老师控制节奏的数学动画舞台”。

## 2. Design Read

**页面类型：**教师控制的线性数学讲解舞台。

**老师和学生：**教师负责推进、提问和暂停；小学生通过画面变化理解数量关系。

**教学任务：**让学生先看见假设法中的基准、差值和逐个替换，再理解计算式。

**视觉气质：**温暖、简洁、带板书感；不是仪表盘，也不是练习游戏。

**信息密度：**低到中。每个时刻只保留当前推理需要的对象。

**动效强度：**中。动作数量不多，但每个动作直接表达数学含义。

**基础视觉参考：**Math Motion Lab 的 `DESIGN.md`。

**交互参考：**本视频的“讲师语句—场景变化—算式揭示”同步方式。

**Keep：**

- 一个稳定数学场景贯穿整段推理。
- 已知条件固定留在场景边缘作为锚点。
- 先具体小例子，后迁移到原题或一般情况。
- 括号、箭头、颜色和局部放大承担指向作用。
- 视觉动作完成后才出现对应算式。
- 最后代回头数与腿数检验。

**Adapt：**

- 用项目现有色彩、字体和课堂外壳替代视频的品牌与手绘皮肤。
- 用代码原生 SVG、HTML 或 Canvas 构造可参数化的数学对象。
- 提高对比度、可读性、键盘操作和 `prefers-reduced-motion` 支持。
- 把线性视频时间轴改为老师可控的教学停靠点。
- 大数量使用明确标注单位的聚合表达，不硬画全部对象。

**Avoid：**

- 不复制视频水印、角色、字体、纹理、声音或精确版式。
- 不把“手绘感”误当成主要目标。
- 不用整页淡入淡出代替数学动作。
- 不用圆角卡片、统计条和结果面板把连续推理切碎。
- 不让说明侧栏重复舞台标题、问题、解释和算式。

**题目专属视觉：**一排保持位置稳定的“头—基础腿—补充腿”对象。假设、差值和替换都发生在这排对象上。

## 3. 视频中的讲解推进

### 阶段 A：用小数量建立直觉

1. 空舞台出现鸡、兔和“10 只、26 条腿”。
2. 出现 10 个头，用括号标出总数。
3. 只展示一个两腿对象和一个四腿对象，让学生看清两类动物的结构差异。
4. 给所有头先配 2 条腿，形成“全部当鸡”的基准。
5. 显示 `10×2=20`，再与实际 26 条腿比较，得到多出的 6 条腿。
6. 局部放大一个对象，显示从 2 条腿变成 4 条腿只需再补 2 条。
7. 把多出的 6 条腿逐组补回场景，3 个对象变成兔。
8. 用括号分出 3 只兔和剩余 7 只鸡。
9. 显示 `3×4+7×2=26` 进行检验。

### 阶段 B：迁移到正式数据

1. 保留同一种头和腿结构，把数据改为“35 只、94 条腿”。
2. 先按全是鸡得到 `35×2=70`。
3. 将实际 94 与假设 70 做视觉比较，突出差值 24。
4. 单独演示一次“鸡式对象 +2 条腿 → 兔式对象”。
5. 用 `24÷2=12` 得到需要替换 12 个对象。
6. 用 `35−12=23` 得到剩余鸡数。
7. 代回头数和腿数检验。

### 阶段 C：检验方法是否通用

1. 换成“独脚兽与四脚蛇”类新对象，但保留相同场景语法。
2. 以 1 条腿为基准，显示 `30×1=30`。
3. 实际 90 与基准 30 相差 60。
4. 单个对象从 1 条腿变成 4 条腿，差值变为 `+3`。
5. 用 `60÷3=20` 得到四脚对象数量，再求剩余独脚对象。
6. 最后检验并把方法总结为“头和与腿和”的假设法。

这个拓展不是为了增加新知识，而是证明学生理解的是“基准与每次替换的差”，不是背诵“鸡乘 2、兔乘 4”。

## 4. 可复用的教学语法

以后设计数量关系课程时，优先检查能否使用以下推理链：

```text
完整题目
→ 建立可见对象
→ 选择一个统一基准
→ 把所有对象放到基准状态
→ 比较实际量与基准量
→ 演示一次单位替换会改变多少
→ 把总差值按单位差值分组
→ 数出替换次数
→ 求出剩余数量
→ 代回原条件检验
→ 换对象或换参数验证迁移
```

不是所有题目都必须使用“假设—替换”，但所有课程都必须找到与本题数学关系对应的一条可见动作链。

## 5. 讲师与界面的同步合同

每个教学停靠点按下面顺序编排：

1. **Ask：**讲师提出一个问题，画面暂不揭示答案。
2. **Pause：**保留可观察证据，让学生回答。
3. **Act：**老师点击下一步，界面执行一个数学动作。
4. **Name：**动作完成后，出现本次动作对应的词语、数字或算式。
5. **Connect：**讲师用一句话把画面变化与算式对应起来。

一个停靠点只解决一个核心问题。一次点击不同时完成“比较差值、分组、求数量、给答案”四件事。

页面步骤、中文讲稿和英文讲稿必须共享同一份停靠点编号。讲稿中的操作要指出界面将发生的具体动作，不能只写“展示下一页”。

## 6. 场景连续性合同

- 开场后确定一套主要数学对象，并在后续步骤中保持位置、尺寸、颜色角色和绘制语法稳定。
- 新步骤优先修改现有对象的状态；只有进入新章节或迁移题时才重建场景。
- 同一数量关系不能无解释地依次变成头像卡片、柱状条、对比卡和统计卡。
- 如果必须切换表示法，先让旧表示法在画面中明确变形成新表示法，或说明为什么要换一种看法。
- 已知条件可以固定在舞台边缘，但不能比当前数学动作更醒目。
- 问题、解释和算式应靠近它们所指向的对象；不要全部抽离到常驻侧栏。
- 公共标题、设置、进度和导航只是控制层，不能抢占数学舞台的主要视觉面积。

## 7. 动效语义合同

允许的主要动效及含义：

| 动效 | 数学含义 |
|---|---|
| 线条绘制 | 建立括号、范围、路径或对应关系 |
| 对象出现 | 引入新的已知对象或证据 |
| 局部放大 | 暂时观察一个单位的内部结构 |
| 增加/减少部件 | 数量发生可解释的变化 |
| 颜色改变 | 对象角色或当前关注点改变 |
| 位移与重排 | 分组、配对、交换或重新组织 |
| 数字递增/递减 | 动作导致的数量变化 |
| 勾选与回代 | 条件检验通过 |

强制规则：

- 常规上一页/下一页不重新播放整个舞台的入场动画。
- 不变对象的边界框应在相邻步骤中保持稳定。
- 只动画本步骤的数学增量。
- 算式在对应动作完成后揭示，不与动作同时争抢注意力。
- 反向导航应恢复可理解的前一状态，不让无关对象再次弹入。
- `prefers-reduced-motion` 下直接显示最终状态，但保留颜色、标注和结构差异。

## 8. 对现有《鸡兔同笼》课件的差距判断

现有页面的数学模型、八步推理和双语讲稿可以保留，但视觉实现存在结构性问题：

- `stage.innerHTML` 在每次翻页时替换整个舞台，场景没有真正连续。
- 头像卡片、鸡卡片、比较条、动物对比卡、腿分组卡和结果卡轮流成为主体，学生需要反复建立新的视觉映射。
- 所有格子会重复播放入场动画，动画表达的是“翻页了”，不是“数学发生了什么”。
- 大量圆角卡片、进度条、侧栏和重复文字让页面更像数据看板，而不是老师正在操作的数学舞台。
- 问题、解释、板书和舞台标题存在信息重复，数学对象获得的视觉面积不足。
- 当前开场的“要找什么”主要位于侧栏和题目摘要，舞台本身没有独立呈现完整所求问题。

后续若重做该课程，应保留经过验证的数学模型和讲稿内容，重做舞台状态模型、对象连续性和语义动画；不需要先推翻计算逻辑。

## 9. 开发前必须交付的场景方案

新建或视觉重做课程的方案除 `Design Read` 和 `Visual Build Sheet` 外，还必须给出：

1. **Persistent Scene：**哪些对象从开场一直保留。
2. **State Delta Map：**每次点击新增、移除、移动或变形什么。
3. **Narration Sync：**讲师在动作前问什么，动作后如何命名。
4. **Representation Change：**如果切换表示法，旧表示法如何过渡到新表示法。
5. **Motion Meaning：**每种动效分别表达什么数学含义。
6. **Reduced Motion：**关闭动画后如何仍然看懂。

没有这六项，不进入大规模实现。

## 10. 验收

- 正常速度连续点击相邻步骤，确认不变对象不闪烁、不跳位、不重复入场。
- 截取开场、核心推理和最终检验三个关键状态，确认它们属于同一视觉世界。
- 每一步都能用一句话说明“画面刚刚发生了什么数学变化”。
- 删除侧栏文字后，学生仍能从舞台看见主要推理关系。
- 删除动画后，最终状态仍能表达相同数学含义。
- 在 `1366×768` 与 `1440×900` 中完整显示舞台和主导航，无页面级滚动。
- 不复制参考视频的品牌、角色、字体、纹理或精确构图。

## 11. 场景版课件落地后的标准结论

`lessons/鸡兔同笼-场景版/` 已把上述视频经验落地成可由老师实际授课的课件。它是以后新题目设计“教师控制单舞台模式”时的首选本地交互参考；旧版 `lessons/鸡兔同笼/` 继续保留，用于对比为什么多卡片、多侧栏和整页重绘会削弱连续推理。

这次落地确认了以下经验：

1. **不是做视频。**老师自己讲解，页面只负责在点击后执行数学动作。
2. **不是自动播放。**舞台空白处、“下一步”或键盘每次只前进一个停靠点，动作完成后立即等待。
3. **不是逐页换版式。**持久 SVG 舞台只初始化一次，后续通过状态切换改变局部对象。
4. **留白是教学资源。**没有新证据时宁可保留空白，也不填入装饰、提示卡或重复说明。
5. **算式必须追随动作。**先出现腿、分组、括号或检验，再显示命名该动作的计算式。
6. **颜色只承担数学角色。**基础量、差额、分组和检验各自使用稳定颜色，不增加无意义的视觉主题。
7. **双语需要重新排版。**英文不是机械翻译；最终检验等长文本应按空间改为上下排列，不能只替换字符串。
8. **最终页仍属于同一场景。**答案不是跳到结果卡，而是在原舞台完成头数、腿数检验后就地出现。

以后新题目不照搬“头和腿”的图形，而要照搬下面这套工作方式：

```text
找到本题唯一的主视觉载体
→ 建立一组可持续存在的数学对象
→ 把讲解拆成一次一个语义增量
→ 让老师点击后只执行这个增量
→ 动作结束后停住并显示对应命名
→ 在原场景中完成检验和最终作答
```

验收时增加一个删除测试：逐项删除装饰、卡片、说明和动效。凡是删除后不影响学生理解当前数学关系的内容，默认不应进入正式课件。
